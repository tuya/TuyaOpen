# qspi

演示 **QSPI**，并把总线驱动成可以直接用逻辑分析仪读出来的样子。

QSPI 和普通 SPI 的区别不在速度，在**结构**：一笔事务分成**命令 / 地址 / dummy / 数据**几个阶段，每个阶段可以独立选择用 1、2 还是 4 根数据线。这是它的价值所在，也是最容易出错的地方 —— 字节可以一个不差，但地址走错了线数、或者 dummy 周期数不对，对面的 flash 照样返回垃圾，而且**所有接口都返回成功**。

例程循环发三笔容易分辨的事务，让这些阶段可以一个一个地看，而不是全糊在一起：

| # | 事务 | 线数 | 长度 @1MHz |
|---|---|---|---|
| 1 | `9F`（只有命令） | 命令 1 线 | 8 clk = **8 µs** |
| 2 | `02` + `12 34 56` + 8 字节数据 | **全 1 线** | 96 clk = **96 µs** |
| 3 | 同上 | 命令/地址 1 线，**数据 4 线** | 48 clk = **48 µs** |

第 2 笔和第 3 笔**内容完全相同，只有数据阶段的线数不同** —— 这是刻意的，方便直接对比。

数据用的是 `00 A5 5A F0 0F CC 33 FF`：`A5`/`5A`、`F0`/`0F`、`CC`/`33` 是三对互反值，**位序或线序如果搞反，这三对会各自对调位置，一眼能看出来**；两头的 `00`/`FF` 方便找阶段边界。

## 这个例程能验什么、不能验什么

**能验**：CS# 是否框住整笔事务、时钟是否只在事务内跑、每个阶段的字节和线数对不对、地址字节序、四线模式下时钟数是否真的减到四分之一。

**不能验**：功能正确性。没有接存储器就没有东西可读回，「对面能不能听懂」需要真器件。

## 配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| `EXAMPLE_QSPI_PORT` | 0 | QSPI 端口 |
| `EXAMPLE_QSPI_FREQ_HZ` | 1000000 | 时钟频率 |
| `EXAMPLE_QSPI_QUAD` | n | 是否发第 3 笔（数据 4 线） |

频率默认压得很低是有意的 —— 没有器件要跟上，而**慢时钟才好抓**。飞线加一根共地，在高速下会把总线变成串扰源，那时候查到的问题往往不在控制器上。

```bash
tos.py config set EXAMPLE_QSPI_FREQ_HZ=10000000 EXAMPLE_QSPI_QUAD=y
```

## 引脚（GD32VW553）

| 信号 | 引脚 | AF |
|---|---|---|
| SCK | PA4 | AF3 |
| CSN | PA5 | AF3 |
| IO0 | PA6 | AF3 |
| IO1 | PA7 | AF3 |
| **IO2** | **PB3** | AF3 |
| **IO3** | **PB4** | AF3 |

⚠️ **IO2/IO3 是 PB3(JTDO) 和 PB4(NJTRST)** —— 开启 `EXAMPLE_QSPI_QUAD` 会把调试口占掉。这就是它默认关闭的原因。串口烧录不受影响。

## 预期输出

```
qspi 0 init at 1000000 Hz
cmd only                     cmd 0x9F, addr 0 byte, data 0 byte on 1-wire -> 0
cmd + addr + data, 1-wire    cmd 0x02, addr 3 byte, data 8 byte on 1-wire -> 0
cmd + addr 1-wire, data 4    cmd 0x02, addr 3 byte, data 8 byte on 4-wire -> 0
```

三个 `-> 0` 表示事务都被接受了。**但返回 0 不代表线上是对的** —— 这个例程存在的意义就是那部分只能看波形。

## 怎么解码

**位序固定 MSB first。** QSPI 没有位序选项（`TUYA_QSPI_CMD_T` 里没有这个字段），串行存储器协议就是 MSB 先出，命令、地址、数据都一样。

> 注意别和隔壁的 [spi](../spi/) 例程混淆 —— 那个例程显式设了 `TUYA_SPI_ORDER_LSB2MSB`，是 LSB。

**第 1、2 笔用 SPI 解码器解更省事。** 它们全在 IO0 一根线上，电气上就是普通 SPI：CLK + MOSI(IO0) + CS，CPOL=0/CPHA=0，MSB first。QSPI 解码器反而需要你手工配全每个阶段的字节数和线数，配不对就是乱码 —— 线上没有任何自描述结构，解码器猜不出来。

**第 3 笔必须用 QSPI 解码器**，参数：命令 1 字节 1 线、地址 3 字节 1 线、dummy 0、数据 8 字节 4 线。

四线模式下每个时钟并行送 4 位，标准映射是 **IO3 为半字节最高位、高半字节先出**：

```
第 1 个时钟：IO3=bit7  IO2=bit6  IO1=bit5  IO0=bit4
第 2 个时钟：IO3=bit3  IO2=bit2  IO1=bit1  IO0=bit0
```

## 判读

| 现象 | 结论 |
|---|---|
| CS# 全程低、时钟只在其中跑 | ✅ 分帧正确 |
| 第 2 笔解出 `02 12 34 56 00 A5 5A F0 0F CC 33 FF` | ✅ 阶段顺序和地址字节序正确 |
| 第 3 笔 **CS# 低电平约 48 µs**（第 2 笔的一半） | ✅ 四线真的生效了 |
| 第 3 笔命令/地址期间 IO1-3 静默，数据期间四线齐动 | ✅ 只有 payload 摊开，这才是 quad flash 写入的形态 |
| **第 3 笔仍是 96 µs、IO1-3 全平** | ❌ 四线没生效，数据还在单线上 |
| `A5`/`5A` 等互反对调换了位置 | ❌ 线序反了（IO0 被当成了半字节最高位） |

## 抓波形的两个提醒

**每根信号线配一根短地线。** 浮地时高速信号会互相串扰，表现是时钟脉宽忽宽忽窄、没接东西的线上有信号 —— 看着像固件问题，其实是测量问题。

**先找路标再找事务。** 一轮里三笔之间隔 50 ms，轮与轮之间隔 1 秒。那个 1 秒的大间隔是路标，**紧挨在它前面的就是第 3 笔（四线）**；或者直接找时长约 48 µs 的那一笔。
