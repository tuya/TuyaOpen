# cpu_sleep

演示 **`TUYA_CPU_SLEEP`** —— 状态保留、原地恢复的低功耗睡眠。

这个模式的承诺是**状态一个不丢**：内存、外设寄存器、网络连接全部保留，唤醒后从停下的那条指令继续执行，**什么都不用重新初始化**。

它**不承诺任何特定的深度**。具体停掉多少由平台决定：有的只停内核时钟、其余照跑，有的连锁相环和晶振一起停。GD32VW553 属于后者 —— 它把 `TUYA_CPU_SLEEP` 映射到芯片的 **Deep-sleep（stop）模式**，所以下面的电流比「只停内核」低得多。

> 这也是这个例程叫 `cpu_sleep` 而不是 `cpu_lightsleep` 的原因。**「浅/深」描述的是芯片手册里的档位，和 TuyaOpen 的 `TUYA_CPU_SLEEP` / `TUYA_CPU_DEEP_SLEEP` 不是一回事** —— 在 GD32 上，`TUYA_CPU_SLEEP` 恰恰落在芯片的 Deep-sleep 上，用「浅睡」称呼它只会造成误解。

**能用哪些唤醒源，同样由平台决定。** 只停内核的平台上任何中断都能叫醒它；停得更深的平台只有常电域的中断还有效 —— 引脚跳变可以，一个普通串口收到字节或者硬件定时器溢出就不行，那些外设的时钟已经停了。

**不需要配置唤醒源。** 调度器的定时由平台内部保证，GPIO 中断按平常方式注册就能唤醒。要显式登记唤醒源的是 `TUYA_CPU_DEEP_SLEEP`。

`TUYA_CPU_DEEP_SLEEP` **不是这个模式的更深一档，而是另一件事**：它不保证状态，可以把芯片断电、从复位醒来，代价是所有东西都要重建。见隔壁的 [cpu_deep_sleep](../cpu_deep_sleep/) 例程。

本例程针对的是**不联网**的设备。已经连上路由的设备走的是另一条路 —— 射频按 DTIM 节律定时醒来，见 [wifi_ps](../wifi_ps/)。

涉及的接口：

- `tkl_cpu_sleep_mode_set(TRUE, TUYA_CPU_SLEEP)` —— 进入睡眠
- `tkl_wifi_set_work_mode(WWM_POWERDOWN)` / `tkl_ble_stack_deinit()` —— 睡前交还用不到的射频

**没有配置项。** 例程不挂任何专门的唤醒源：调度器自己的 systick 每 2 秒就会把内核叫醒一次。挂一个按键中断不会多证明任何东西，反而会让人误以为这个模式需要专门的唤醒源。

## 为什么要先关射频

这不是可有可无的省电小优化，在有些平台上它决定内核**能不能睡**。

射频协议栈跑起来之后会向电源管理登记「我还要用 CPU」。只要没人告诉它可以停，这个登记就一直有效，内核连一次 `__WFI()` 都执行不了 —— 而且完全无声，日志正常、接口全部返回成功，只有电流会说话。

所以一个不用 WiFi 和蓝牙的设备，应该通过标准接口明确交还它们：

```c
tkl_ble_stack_deinit(0);
tkl_wifi_set_work_mode(WWM_POWERDOWN);
```

在 GD32VW553 实测：不关射频 39.3 mA（内核全程空转），关掉之后 **1.28 mA**。**同一份固件，只差这两行调用。**

## 预期输出

```
Reset reason:        6 (external pin)
ble  stack deinit -> 0
wifi power down   -> 0
enter cpu sleep -> 0
alive 1
alive 2
alive 3
```

- 两行 `-> 0` 表示射频交还成功；返回负数说明该平台没有对应实现，不影响后面的睡眠
- `enter cpu sleep -> 0` 表示睡眠模式配置成功
- `alive N` 每 2 秒递增一次，说明内核在心跳之间睡过又醒来，而且状态没丢

## 怎么确认内核真的停过

上面这些**都不能**证明睡眠生效 —— 一个从没睡过的内核，日志一模一样。要证明内核停过，得看它在这段时间里干了多少活。

最直接的软件判据是**退休指令数**：内核如果在空闲循环里自旋，每秒退休上亿条指令；如果停在等待指令上，这段时间一条都不退休。多数 MCU 都有这个计数器（RISC-V 是 `minstret`，Cortex-M 需要 DWT）。在 2 秒心跳的前后各读一次，差值从 10⁸ 量级掉到 10⁴ 量级，就是内核确实停了。

注意**周期计数器（RISC-V `mcycle`）不能用作判据** —— 它在不少实现里由自由运行的时钟驱动，内核停了照样计数。

省了多少电是另一个问题，软件量不出来，要在供电回路串电流表。

## 平台支持情况

不是所有平台都实现了这个模式。如果日志显示：

```
enter cpu sleep -> -1
this platform has no cpu sleep mode wired up; staying awake
```

说明该平台的 `tkl_cpu_sleep_mode_set` 没有处理 `TUYA_CPU_SLEEP`。例程会继续正常运行。

## 关于功耗

这个模式的卖点是**唤醒延迟低、上下文完整保留**，适合需要随时响应的场景。省多少电则完全看平台停掉了什么。

在 GD32VW553 上（整板，含开发板的电源 LED 和 USB 转串口）：

| 状态 | 平均电流 |
|---|---|
| 内核不睡 | 39.3 mA |
| **`TUYA_CPU_SLEEP`** | **1.28 mA** |

这颗片子把锁相环和晶振也停了，所以数字很低；换个只停内核的平台，同一份代码可能只降三成。**比值和绝对值都是平台相关的，别跨平台照搬。**

GD32VW553 上这个模式的完整能力边界（哪些外设还能用、为什么 PWM 和硬件定时器不能）见 [`boards/GD32/doc/LOW_POWER.md`](../../../boards/GD32/doc/LOW_POWER.md)。
